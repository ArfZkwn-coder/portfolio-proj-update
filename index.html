Case study

Docs Publisher MCP Connector

Status
Side project, self-hosted
Built with
Node.js, MCP SDK, GitHub API, Docker, Tailscale Funnel

The problem

Publishing a tutorial to a Git-based docs site means cloning the repo, writing Markdown, committing and redeploying. That keeps non-developers out and slows everyone else down.

How it works

  • Seven MCP tools let Claude list, read, publish, edit and delete tutorials, add images and redeploy the site. It works with Docusaurus, MkDocs, VitePress and other Git-based generators.
  • Every change commits straight to the docs branch on GitHub, and the site rebuilds in the background. Changes that arrive mid-deploy are folded into one more deploy.
  • Images are stored in the docs repo rather than hotlinked. Uploads accept only JPEG, PNG, GIF and WebP up to 5 MB, check the file's real bytes, and refuse private-network addresses so the server cannot be used to reach its own network.
  • It runs in Docker on my homelab and is reachable from claude.ai through Tailscale Funnel, with no router ports opened. Each person gets a personal key that can be revoked on its own, and every commit records who asked for it.
  • n8n workflows and a Telegram bot hand out and revoke access through a private admin API that is never exposed to the internet.

Outcome

Publishing a tutorial is a sentence to Claude instead of a Git workflow, and each person gets their own key that can be revoked on its own.

Stack

  • MCP
  • Node.js
  • GitHub API
  • Docker
